# KB 03 — Website Blueprint

## Purpose
Convert PROJECT_CONTEXT + WEB_INTELLIGENCE into an approved implementation plan before WordPress execution.

## Decisions
- site architecture and page map
- navigation and conversion path
- page purpose and hierarchy
- section order
- block-level composition
- CTA system
- design direction handoff
- asset requirements handoff
- functional dependencies
- responsive intent

## Page/block structure
Each page must be decomposed into sections and blocks. Each block records:
- ID
- name
- objective
- user need
- business goal
- layout
- content role
- CTA
- visual treatment
- motion
- asset references
- responsive behavior
- accessibility notes
- technical dependencies

## Rules
- Never default to a fixed template just because it is familiar.
- Architecture must follow project goals, content volume, evidence and user journey.
- Do not hide important conversion information without strategic reason.
- Keep visual decisions consistent with DESIGN_FINGERPRINT.
- Every required image/media item must map to ASSET_MAP.

## Gate 1 package
The blueprint shown for approval must include:
- architecture
- pages
- sections/blocks
- Design Fingerprint summary
- asset plan
- motion/interaction notes
- functional requirements
- known assumptions/risks

No production action before explicit Gate 1 approval.
